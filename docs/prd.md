# 하루동화 프론트엔드 데모 PRD

기존 프로젝트를 확인한 후, 아래 지시를 기준으로 '하루동화' 프론트엔드 데모를 완성해줘. 기획 제안만 하지 말고 실제 화면, 문구, 이미지 에셋, 상호작용까지 구현해줘.

기존에 구현된 기능은 유지하며 수정한다. 디자인과 문구가 충돌하면 이번 지시를 우선한다.

## 1. 서비스 정체성

서비스명: 하루동화
슬로건: 우리 아이의 하루가, 한 권의 동화로.

하루동화는 부모가 아이의 사진과 짧은 일화를 쉽게 기록하고, 쌓인 추억과 아이에게 전하고 싶은 교훈을 바탕으로 AI가 아이를 주인공으로 한 그림동화를 만드는 서비스다.

두 핵심 기능을 모두 명확히 전달한다.

1. 사진과 짧은 글로 간편하게 남기는 아이 성장 기록
2. 기록 속 경험과 부모가 선택한 교훈을 연결해, AI가 이야기와 삽화를 구성하는 맞춤 그림동화

AI는 서비스의 핵심 가치로 적극 설명한다. 다만 현재 구현은 프론트엔드 데모이므로 실제 AI가 작동한다고 오해하게 만들지 않는다.

소개 페이지에서 설명하는 서비스의 목표 기능과 현재 체험 기능을 구분한다. 체험 화면에는 "미리 준비된 예시로 체험하는 AI 그림동화입니다"라는 안내를 제공한다.

실제 사진 속 아이의 외모를 자동으로 정확히 재현하거나, 발달을 분석하거나, 교육 효과를 보장한다는 문구는 쓰지 않는다.

## 2. 구현 범위와 경로

기존 React + Vite + TypeScript, React Router, TailwindCSS, lucide-react를 사용한다. 상태는 React Context/state, 데이터는 src/mock/에서 관리한다.

기존 3개 앱 화면을 유지하고 서비스 소개 상세페이지를 추가한다.

* /intro: 서비스 소개 상세페이지
* /: 캘린더 기반 성장 기록 홈
* /diary/:date: 기록 작성·조회·수정
* /storybook: 동화 만들기·로딩·결과

소개 페이지의 '하루 기록 시작하기'는 /로 이동한다.
'그림동화 미리보기'는 소개 페이지 내 예시 동화 영역으로 이동한다.
앱에서도 로고 옆 메뉴 또는 보조 링크로 서비스 소개에 접근할 수 있게 한다.

로그인, 결제, 백엔드, 데이터베이스, 실제 사용자 데이터 AI 처리, 실제 파일 서버 업로드는 구현하지 않는다.

개발 과정에서 소개용 삽화 에셋을 생성하는 것은 요청 범위에 포함한다. 이것과 앱 실행 중 사용자 사진을 AI API로 보내는 기능은 구분한다. 런타임 AI 호출은 구현하지 않는다.

## 3. 전체 디자인

따뜻하고 완성도 높은 그림책 서비스로 만든다. 실제 부모가 사용하기 편하도록 정보와 조작부는 명확하게 구성한다.

색상:

* 기본 배경: 따뜻한 아이보리 #FFF9F0
* 민트: #A8DAD0
* 옐로우: #FFE5A0
* 코럴: #FFB4A2
* 본문: 짙은 브라운 계열 #453D38

파스텔 색상을 넓은 바탕에 사용하고, 본문과 버튼 글자는 충분한 대비를 확보한다.

제목은 둥글고 부드러운 한글 서체, 본문은 읽기 좋은 sans-serif를 사용한다. 외부 폰트 로딩 실패에 대비한 대체 서체를 지정한다.

넓은 여백, 둥근 모서리, 은은한 그림자를 사용한다. 모든 요소를 카드로 감싸서 화면이 잘게 분절되지 않도록 한다.

소개 페이지는 큰 삽화와 실제 그림책 펼침 구성을 중심으로 디자인한다. 일반적인 AI SaaS 대시보드처럼 만들지 않는다.

모바일에서 터치 영역과 글자 크기를 충분히 확보한다. 과한 패럴랙스, 자동 슬라이드, 끊임없이 움직이는 장식은 넣지 않는다.

## 4. 아기 마스코트와 그림 스타일

대표 마스코트는 동물이나 로봇이 아닌 '아기 캐릭터'로 만든다.

마스코트 이름: 하루

외형:

* 2~3세 정도의 귀여운 그림책 속 아기
* 동그란 얼굴과 통통한 볼
* 짧고 짙은 갈색 머리
* 작은 새싹 모양의 앞머리
* 크림색 상의
* 민트색 멜빵옷
* 작은 코럴색 포켓
* 부드러운 표정과 단순한 형태

성별을 강하게 강조하지 않는다. 유명 캐릭터나 특정 작가의 스타일을 그대로 모방하지 않는다.

마스코트는 브랜드 안내 캐릭터다. 실제 사용자의 아이 사진으로 만들어진 캐릭터라고 설명하지 않는다.

필요한 포즈:

* 손을 흔드는 기본 포즈
* 작은 그림책을 읽는 포즈
* 연필로 기록하는 포즈
* 책을 안고 기뻐하는 포즈

삽화 스타일:

* 따뜻한 파스텔 수채화와 색연필 질감
* 종이의 부드러운 질감
* 둥글고 단순한 형태
* 자연스럽고 따뜻한 빛
* 실제 유아 그림책에 어울리는 장면 구성
* 사진처럼 사실적인 피부나 3D 플라스틱 장난감 질감은 피함

같은 아이가 등장하는 모든 삽화에서 얼굴, 머리, 옷, 색상을 일관되게 유지한다. 먼저 기준 캐릭터 이미지를 만들고, 가능한 경우 이를 참조해 다른 장면을 생성한다.

## 5. 이미지 에셋 제작 — 필수

소개 상세페이지에 일반 스톡 사진, 무작위 풍경 사진, picsum 이미지를 사용하지 않는다.

실제로 AI 그림동화책 예시처럼 보이는 삽화를 제작해 넣는다. 이모지나 단색 카드만 배치하고 이미지 제작을 완료했다고 처리하지 않는다.

사용 가능한 이미지 생성 도구 또는 이미지 생성 스킬이 있는지 먼저 확인하고, 있다면 사용해 실제 이미지 파일을 생성한다. 실행할 수 없는 도구나 권한을 있다고 가정하지 않는다.

필요 에셋:

1. 히어로 삽화 1장
2. 아기 마스코트 포즈 4종
3. 아래 예시 그림동화의 장면 삽화 5장

히어로 삽화:
민트색 멜빵옷을 입은 아기 '하루'가 커다랗게 펼쳐진 그림책 위에 앉아 있다. 책 속에는 작은 정원, 꽃, 별, 종이 형태의 추억 조각들이 자연스럽게 이어진다. 아이의 일상이 그림책 세계로 확장되는 느낌이다. 따뜻한 아이보리 배경과 파스텔 수채화 질감을 사용한다.

이미지 안에 한글 제목이나 설명을 생성하지 않는다. 모든 문구는 HTML 텍스트로 얹어 가독성, 반응형, 접근성을 확보한다.

권장 비율:

* 히어로: 4:3 또는 3:2
* 동화 삽화: 3:2
* 마스코트: 투명 배경 또는 배경 제거가 쉬운 단색

생성된 에셋은 프로젝트 내부에 저장하고 직접 참조한다. 외부 임시 이미지 URL에 의존하지 않는다. 이미지 크기를 최적화하고 아래 영역은 지연 로딩한다. 이미지에 적절한 대체 텍스트를 제공한다.

이미지 생성 수단이 전혀 없으면 이미지 생성이 막혔음을 명확히 보고한다. 나머지 구현을 계속하고, 임시 자체 제작 삽화를 사용하되 이를 AI 생성 이미지라고 주장하지 않는다. 최종 보고에서 이미지 제작 항목을 미완료로 표시한다.
